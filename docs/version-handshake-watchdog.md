# Module version handshake + watchdog flow (added 2026-07-20)

**Problem solved**: the npm package and the `.mod` file actually loaded on the controller can silently drift (palette updated, module not re-flashed) → confusing unrelated-looking errors. Separately, a self-healing watchdog for the still-unexplained socket-wedge bug (`.claude/memory/project_socket_server_stuck_2026-07-15.md`) needed a real recovery flow, not just diagnostics.

**Version handshake**: `MainModule.mod`, `MainModuleEGM.mod`, `BackgroundLed.mod` each declare `CONST string MODULE_VERSION` (kept in lockstep with `package.json`), included in the `ping` JSON reply. `socketSend()` records the reported version per-port (`getLastPingVersion(port)`; omit for T_ROB1, pass `robot.backgroundPort` for `BackgroundLed.mod`) — `null` if no successful ping yet, or module predates the feature. `PALETTE_VERSION` (from `gofa-robot.js`, reads `package.json` live) is the single source of truth for "expected."

`gofa-connection-status` surfaces `msg.payload.moduleVersion.{socket,background}` = `{version,status}`, `status` ∈ `match`/`mismatch`/`unknown`, plus `.expected`. A mismatch on an otherwise-healthy result sets yellow status without affecting `payload.ok`.

**Runtime comparison is major.minor only (2.4.11)** — `versionsCompatible(a,b)` (exported from `gofa-robot.js`) treats matching `major.minor` as `match`; patch skew never warrants a re-flash nag since patches never change the socket protocol. `test.js`'s own drift check is still exact-string (repo hygiene, separate concern from runtime tolerance). `gofa-setup`'s final PING step folds this into its `detail` string.

**Watchdog flow (`flows/watchdog_flow.json`)**: 30s inject → reentrancy guard (`flow.get('watchdogRecovering')`) → `gofa-connection-status` → wedge-signature check: **`rws.ok && rws.rapid==='running' && socket.ok===false && !egmActive`** (RAPID *claiming* to run while its socket is dead = genuinely wedged; a legitimate stop has `rapid==='stopped'`, not wedged) → `switch` gate → on wedge: evidence capture (`gofa-elog` then `gofa-rapid-tasks`, run **sequentially**, not fanned out in parallel — an earlier draft double-fired downstream nodes) → recovery chain `stop` → (clear payload) → `resetpp` → (clear payload) → `start` → (clear payload) → `gofa-connection-status` recheck → bundle evidence+outcome, clear reentrancy flag → `debug` (notification integration left as an extension point, not built).

**`egmActive` exclusion — a real bug caught the day after shipping.** An active `gofa-egm` session has the identical `{rapid:'running', socket down}` shape as a genuine wedge (EGM deliberately never stops the task). Without the exclusion, any EGM session running past one 30s poll would be misdiagnosed and force-recovered mid-session. Fixed: `egmActive: !!r._egmActive` added to `gofa-connection-status`'s payload, `&& !egmActive` added to the wedge condition.

**Live-tested**: wedge-detector correctly returns false both while RAPID is legitimately stopped and while healthy; individual recovery mechanics (stop→resetpp→start→recheck) driven live via the real node files. **Not live-tested**: the flow's actual end-to-end wedge trigger path (deliberately reproducing the unresolved wedge bug live was judged too risky) — decision logic and recovery mechanics were each verified independently instead.
